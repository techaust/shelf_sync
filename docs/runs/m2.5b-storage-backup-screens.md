### What to build
1. **Settings › Storage** (replaces the "later version" panel), on `GET`/`PUT /api/settings/storage` and `PUT`/`DELETE /api/secrets/s3-rw` and `/api/secrets/s3-ro`:
   - **The settings:** endpoint (empty means Amazon S3), region, bucket, "Previous files to keep" (1–5) and the download link template. Each field is checked in the form with the API's rules, and the server's answer is the one that counts. Save sends all five.
   - **Two key pairs** ("Read and write", "Read only") as SecretField pairs:
     - the key ID mask, the secret as `••••`, "Not set", or "Couldn't be read" when `keys_readable` is false;
     - trim spaces around a pasted key ID or secret before sending (AWS CSV copies often carry them);
     - Save sends a pair; Remove asks first in a ConfirmDialog.
   - **No Test button.** In its place, the line "Testing the bucket arrives with the S3 update. Your settings and keys are saved." (proposed in m2.0; keep it, or propose better wording). When the region or bucket is empty, add 13's "Region and bucket must be filled in before the bucket can be tested."
   - A link to the S3 guide in the Help panel (m2.5a).
2. **Settings › Backup** (replaces the "later version" panel):
   - **Daily backups**, from `GET`/`PUT /api/settings/backup`:
     - the last backup's time (local time with the zone name) and size;
     - the next one's time;
     - how many are kept;
     - the two settings: "Database backups to keep" (1–30) and "Keep snapshots for" (1–365 days; stored now, used from M3: say so in one line).
     - Restoring is a command, not a button: link the restore runbook's one-line summary, with 13's restore wording.
   - **Export:**
     - "Export settings", with the "Include secrets (needs a passphrase)" checkbox and a passphrase field (12–1024 characters, with a second field to confirm it, checked in the form);
     - the download is made from the response as a Blob, named from `Content-Disposition`;
     - when the `X-ShelfSync-Left-Out` header is present, show 13's left-out line with the store names (from `GET /api/stores`) and the slot names;
     - the passphrase is cleared from the page after each attempt, success or not.
   - **Import:**
     - "Import from file…" through a file picker; read the file with `File.text()` only after checking `File.size` is at most 1 MiB, otherwise answer with 13's `export_invalid` text without sending;
     - a passphrase field, offered when the file says it is encrypted (read the header's `encryption` field in the page; the server's answer still decides);
     - the result in 13's wording, which differs for an encrypted file and a plain one (`encrypted` in the answer), including the restart line;
     - every error code with its 13 text, and "Nothing was imported." where 13 has it;
     - `import_needs_empty` explains that import is for a fresh install or a new PC.
   - Export and import are turned off while one runs; `busy` uses its 13 text.
