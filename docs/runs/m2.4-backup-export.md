# M2.4: backup export and import

## 1. Brief

### PRD IDs
SET-05 ("Export/import settings + catalog as one file (secrets only with a passphrase)"). The catalog arrives in M3, so `catalog` is `null` in format version 1. The screen is m2.5b.

### Agent and skills
- **`builder`:** Sonnet 5.5 at high, in its own worktree, after m2.1, m2.2 and m2.3 are merged. It never pushes. Context7 for cryptography's `AESGCM` (tag placement, nonce size, size limits) and Python's `hashlib.scrypt`.
- **Don't load** `code-review` or `security-review`.

### Decided already (don't change)
- **KDF** ([11](../11-decisions.md) 2026-10-25, 04 §2, 06 §7, 04-A V21): the standard library's `hashlib.scrypt(password=NFC(passphrase).encode("utf-8"), salt=<16 random bytes>, n=2**17, r=8, p=1, maxmem=256*1024*1024, dklen=32)`. Not cryptography's Scrypt.
- **Cipher:** AES-256-GCM from `cryptography.hazmat.primitives.ciphers.aead.AESGCM`, a 12-byte random nonce, a new salt and nonce for every export.

### What to build
Follow [m2.0-plan.md](m2.0-plan.md) §1 "m2.4-backup-export" exactly:
1. **`secure/backup_crypto.py`:** pure `seal(payload_bytes, passphrase) -> envelope` and `open(envelope, passphrase) -> payload_bytes`, no I/O.
2. **The `.ssbak` file**, UTF-8 JSON: `{"format":"shelfsync-export","version":1,"created_at":<UTC ISO>,"app_version","schema":<highest migration>,"encryption": null | {"cipher":"AES-256-GCM","kdf":"scrypt","n":131072,"r":8,"p":1,"salt":<b64>,"nonce":<b64>}, …}` plus `payload` and `sha256` (hex of the canonical payload; corruption check only) when unencrypted, or `ciphertext` (b64) when encrypted.
   - **AAD** = the canonical JSON (`sort_keys=True`, `separators=(",",":")`, `ensure_ascii=True`) of every header field except `ciphertext`.
   - Import accepts **only** `n=131072, r=8, p=1` for version 1: costs are never taken from the file, and a raised cost is refused before any derivation.
   - Duplicate JSON keys refused (`object_pairs_hook`), unknown fields refused.
3. **Payload v1** (`db/export.py`): `{"settings": {every setting key}, "stores": [{code, name, url, shape, color, spacing_ms, main_button, state}], "storage": {the m2.3 settings}, "catalog": null, "secrets": {"stores": {"<code>": {consumer_key, consumer_secret}}, "s3": {the four}, "github_token": <str|null>}}`. `secrets` appears **only** in encrypted files. The install token is **never** exported.
4. **Passphrase:** 12–1024 characters after NFC, never logged, registered with `redact` for the request's life.
5. **API `api/backup.py`** (behind the guard, in the route walk):
   - `POST /api/backup/export` `{passphrase: str | null}` → 200 `application/json`, `Content-Disposition: attachment; filename="shelfsync-export-<local date YYYY-MM-DD>.ssbak"`; 409 `busy` (one KDF at a time, process-wide).
   - `POST /api/backup/import` `{file: str (the file's text, ≤ 32 MiB), passphrase: str | null}` → 200 `{stores, settings, secrets}` (counts); 422 `export_invalid`, `passphrase_required`, `wrong_passphrase`; 409 `export_too_new` (a newer format version or schema), `import_needs_empty` (the install already has a live store: import is only for a fresh install or a new PC), `busy`; 503 `secrets_unavailable`.
   - Check the request body size limit the app enforces today (the guard or uvicorn); raise it for this route only if needed, and say how.
6. **Import order:** size cap → parse → header check → decrypt and check the tag (or the SHA-256) → validate the whole payload with the same Pydantic models the settings and store APIs use → **only then** one DB transaction, with the Credential Manager writes before the commit; on any failure roll back and delete the entries already written. Imported store secrets are registered with `redact`.
7. **Strings:** proposed 13 wording in the report (the mockup has "Can't open shelfsync-export.ssbak: the passphrase doesn't match." + "Nothing was imported.").

### Tests (07 §1 "Backup")
Round trip with and without a passphrase (the real scrypt parameters at least once; others may patch the cost through a test-only seam that production code can't reach); a wrong passphrase fails cleanly and changes nothing; tampered ciphertext, header, AAD, salt, nonce or KDF parameters fail; raised KDF costs refused before any derivation (assert scrypt isn't called); a plain file holding `secrets` refused; oversize, unknown version, newer schema, duplicate keys refused; the install token never in an export; the passphrase never in a log (`test_never_logged.py`); a failure halfway (a fake secret store failing mid-import) leaves no row and no entry; `import_needs_empty`; `busy`; the guard and the route walk. hypothesis: any single-byte change to the ciphertext fails.

### Done means
ruff, format, mypy **and `uv run mypy --platform linux`**, pytest, bandit, pip-audit; `npm run schema:check` after regenerating the schema; ≥ 90 % coverage on `secure/`; `packaging/smoke.py` gains one `hashlib.scrypt(b"x", salt=b"0"*16, n=2**17, r=8, p=1, maxmem=256*1024*1024, dklen=32)` call so the embedded Python's OpenSSL is proven (then the lead runs `release-build.ps1`); the report in §3.

### Out of scope
The screen (m2.5b); the catalog (M3, format version 2); merging an import into an install that has stores.
