### V57: what the tests showed
Setup: Python 3.15.2, OpenSSL 3.5.9, cryptography 50.0.2, httpx 0.28.1, httpcore 1.0.9. Every client context is `ssl.create_default_context(cafile=<one certificate file>)` with nothing changed: `VERIFY_X509_STRICT` on, `check_hostname` on, `CERT_REQUIRED`. `cert_store_stats()` is `{"x509": 1, "crl": 0, "x509_ca": 0}`, so it trusts that file only.

**The look-alike.** Before making it, I read the public fields of `C:\laragon\etc\ssl\laragon.crt` (read-only, with `cryptography`; `laragon.key` wasn't opened). Two things there go beyond the brief's facts:
- Its SANs also include the IP `127.0.0.1` and one LAN address. The LAN address is left out of the repo.
- Its extensions are basicConstraints `CA:FALSE`, keyUsage digitalSignature + keyEncipherment, extendedKeyUsage serverAuth, and a subject key identifier. It has **no** authority key identifier, and none of the extensions is critical. It's RSA 2048 with SHA-256.

`tests/tls_support.py` `make_certificate()` copies that shape, and a test pins it.

**SNI and the hostname check on the `.test` name, with the socket going to 127.0.0.1.** The test-only `LoopbackTransport` (an `httpx.BaseTransport` wrapper) rewrites only the request URL's host and port to `127.0.0.1:<port>`. It sets httpcore's documented `sni_hostname` request extension to the original name. The `Host` header was already fixed from the original URL when the request was built.
- No name is looked up (the conftest guard stays on), and the TLS context is used unchanged.
- The test server records the SNI name it received and the `Host` header.
- I chose this over a custom httpcore network backend because httpx 0.28.1's `HTTPTransport` takes no `network_backend`, so that route would mean replacing its private `_pool`.
