#### What was built

- **The site guard (`parse_site`).** Only `https://<labels>.test[:port]` passes. It refuses `http`, any other suffix, IP addresses, `localhost`, user info, a path, a query, a fragment, a trailing dot and bad labels. argparse refuses before anything else runs (exit 2), with "The test stack never talks to a real store."
- **Every socket goes to 127.0.0.1 (`LoopbackOnlyTransport`), not only in tests.** It rewrites the URL host to 127.0.0.1, keeps the port, and sets `sni_hostname` to the site name. So SNI, the hostname check and the `Host` header stay on the site, and a key can't leave this PC even if a `.test` name resolved elsewhere. It wraps `httpx.HTTPTransport(verify=<context>, trust_env=False)`.
  - **This goes beyond the brief**, which says `transport=httpx.HTTPTransport(verify=<context>)`. It's stricter, and the real check no longer depends on the hosts file. Open question 1.
- **`tls_context(cert)`** is `ssl.create_default_context(cafile=<file>)`.
  - It checks, never sets: `VERIFY_X509_STRICT`, `check_hostname`, `CERT_REQUIRED`. If one is off, it refuses to connect.
  - It refuses a file with no certificate (a key given by mistake) or with more than one.
- **`cert`** makes the site's certificate, its key and an Apache site file.
  - **The certificate:** `make_site_certificate`, RSA 2048, SHA-256, self-signed. basicConstraints `CA:FALSE` (critical), keyUsage digitalSignature + keyEncipherment (critical), serverAuth, SAN exactly the site name, SKID. Valid from an hour ago for 365 days.
  - **The key and certificate files** go in `C:\ShelfSync-TestStack\tls\<site>.crt` and `.key` (`--dir`). Why this folder: open question 2.
  - **The key** is created empty and exclusively (`O_EXCL`). It's then limited to the current account before anything is written into it: `icacls /inheritance:r /grant:r *<SID>:(F)`, with the SID from `whoami /user`, both from `%SYSTEMROOT%\System32`. Off Windows it's mode 0600. If limiting fails, the empty key file is deleted and nothing else is written.
  - **The Apache file** is `C:\laragon\etc\apache2\sites-enabled\00-<site>.conf`: `<VirtualHost *:<port>>`, `ServerName`, the Laragon project's `DocumentRoot` and `<Directory>` (AllowOverride All, as Laragon's template has), `SSLEngine on` and the two files.
  - **Why `00-`:** Apache reads `sites-enabled/*.conf` alphabetically and the first matching `ServerName` wins (Apache docs). `00-` sorts before Laragon's `auto.<site>.conf`, so Laragon's file is never edited.
  - **Its checks:** it needs Laragon's `etc\apache2\sites-enabled` and `www\<project>` to exist. It refuses to replace any of the three files without `--force`.
  - **It prints** the expiry date, the SHA-256 fingerprint, the three paths, and the next step (Laragon's documented `laragon.exe reload apache`).

  - **Different:** a `PUT` of the differing fields only, keeping download IDs where name and file match.
  - **The wrong type, or in or out of the trash when it shouldn't be:** force-deleted and created again. That way `seed` never relies on editing a trashed product, or untrashing one, through REST, neither of which is confirmed.
  - **Variations:** matched by their own marker, the same way.
- **The files:** they go to moto before the products, on every run, through ShelfSync's own `make_client` (`testenv.moto_s3.s3_client`).
  - **Probe:** a 0.5-second TCP check runs first, because botocore retries a refused connection for seconds. Without moto, `seed` says so and still seeds the products, with exit 0.
  - **Refused `--moto` values:** anything that isn't `http` on 127.0.0.1 or localhost with a port (argparse, exit 2).
