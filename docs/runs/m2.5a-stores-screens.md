### What to build
1. **Settings › Stores** (replaces the "later version" panel), on `GET /api/stores`, `POST /api/stores`, `PATCH /api/stores/{id}`, `PUT /api/stores/{id}/keys`, `DELETE /api/stores/{id}` and `POST /api/stores/{id}/test`:
   - **One card per store**, as the mockup has it: name, address, the identifier (shape, colour key, two-letter code) with a live StoreBadge preview, "Time between requests" in seconds (shown with up to two decimals, sent as `spacing_ms`, 0.05–5 s), the main-button choice, and the state (live or paused).
   - **Keys:** the consumer key and secret as one SecretField pair. The API returns masks only: show the mask, "Not set", or, when `keys_readable` is false, "Couldn't be read" (never "Not set" then). A new pair is always sent as a pair and the inputs are cleared after a save.
   - **Address change:** when the address's host changes, the API answers `keys_required` unless new keys come in the same request. The card asks for them together, with the 13 text.
   - **Test connection:** shows the 13 result ("Connected in N ms. WooCommerce X, N downloadable products.") or the reason, with `tested_at` in Windows local time with the zone name. While it runs, the button shows progress and a second click does nothing; `busy` uses its 13 text.

   - **Add a store:** an empty card. When 50 live stores exist the API answers `too_many_stores`; show its 13 text.

A code another store uses is refused by the API (`code_taken`); show it at the field. **Don't add colour pairs.** If you think more are needed, propose up to four in the report, each with its 3:1 contrast result on every surface, for the owner's approval.

   - paused stores show as paused, never as failed.
3. **The Help panel** (UI-HELP, guides only), opened from each screen's header as in the mockup, with a native `<dialog>` like ConfirmDialog (Esc closes it, and the focus returns to the opener):
