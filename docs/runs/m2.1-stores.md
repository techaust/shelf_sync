### Design notes the lead should know
- **Structure.** `db/stores.py` (repository, never commits), `secure/credentials.py` (`StoreCredentials`: names `store-<id>-key`/`-secret`, masks, atomic pair, redaction registration), `apply/woocommerce.py` (`WooClient` with only `get`/`close`; `GetOnlyTransport`; `run_read_test`), `store_service.py` (`StoreService`: rules, transactions, one test per store), `api/stores.py` (models and routes). `StoreService.in_memory()` is the default for `create_app` (shared-cache in-memory SQLite plus `MemorySecretStore`); `build_store_service(paths, secrets)` is the real one.
- **Atomic save:** row inserted/updated in `BEGIN IMMEDIATE`, both entries written, then `COMMIT`; any failure rolls back and removes/restores entries (`save` puts the old pair back; `delete` restores the first entry if the second delete fails, so a failed Remove changes nothing).
- **Extra response fields** (beyond the brief's list, both optional strings): `StoreTestResponse.detail` (the redirect target host, host name only, lowercase) and `.warning` (`no_downloadable_products`, the "count 0 is ok with a warning" case). Neither is stored; `GET /api/stores` health shows `redirected` without the host.
- A test failure saves its result like a success (versions kept when the first GET succeeded, else cleared).
- **Host change** = host or port differs (`netloc`); a path-only change resets health but needs no keys. Sending the same URL again (after normalisation) keeps the last test. Sending the key pair on a PATCH is also allowed without a host change (it replaces the keys and resets the health).
- URL rules: https only; host must be a DNS name with at least one dot and a non-numeric last label (so `localhost`, `127.1`, `0x7f.1`, IP literals are refused); `:443` is dropped; path allowed (`[A-Za-z0-9._~/%-]`, no `//`, no `.`/`..` segments); no userinfo, query, fragment, backslash, space or non-ASCII; at most 200 characters.
- `ErrorCode` appended: `not_found`, `store_exists`, `code_taken`, `keys_missing`, `keys_required`, `secrets_unavailable` (`busy` already existed). Same six in `KNOWN_CODES`.
- **Uninstall:** `uninstall.store_secret_names(db)` opens the database `mode=ro`; no database or no `store` table gives no names; an unreadable database prints "Couldn't read the list of stores, so their Credential Manager entries may be left." and ends in exit 5 (exit 6 if data was left too). Consequence: a data folder whose `shelfsync.db` isn't a real database now exits 5; `tests/test_uninstall.py`'s `make_data` and `test_main_needs_the_flag...` now create a real (empty or migrated) database instead of the text "db". The installer script's wording for exit 5/6 is unchanged.
- **Existing tests adjusted** because 0002 exists now: `test_db.py` (fresh DB gets 1 and 2, three tables incl. `sqlite_sequence`); `test_update_switch.py` rig's `SwitchEnv` now sets `own_schema=lambda: 1` (the simulated running release is at schema 1; it used to read the source tree's latest, which is 2 now).
- **server.py merge note:** the `serve(create_app(...))` call in `_start` changed from one line to a multi-line call that adds `stores=stores`, plus two lines before it. If m1b.3 also edits that call, resolve by keeping both keywords.
- Logs: a store appears as its code (`Store SA read test: keys_refused (HTTP 401)`); "Store SA was added/removed". The `httpx` logger isn't turned down here (it is at WARNING in `update/github.py` at import, process-wide); the client logs nothing with a URL itself.

### Proposed wording for docs/13 (owner-facing strings)
Health reasons (shown with the HTTP status where there is one; "HTTP 401: the Shop Manager key was refused." and "Connected in N ms. WooCommerce X, N downloadable products." are the mockup's):
- `unreachable`: "Couldn't reach the store. Check the address and your internet connection."
- `timeout`: "The store took too long to answer."
- `tls_error`: "The store's security certificate wasn't accepted."
- `redirected`: "The store sent the request to another address ({host}). Update the store's address."
- `blocked`: "Something in front of the store (a firewall or a security check) blocked the request."
- `not_woocommerce`: "That address answers, but it isn't a WooCommerce store's REST API."
- `rate_limited`: "The store is limiting requests (HTTP 429). Try again in a few minutes."
- `cloudflare_52x`: "Cloudflare couldn't reach the store's server (HTTP {status})."
- `server_error`: "The store had an error (HTTP {status})."
- `bad_response`: "The store's answer wasn't what ShelfSync expected."
- `keys_refused`: "HTTP 401: the Shop Manager key was refused."
- `forbidden`: "HTTP 403: the key is valid but isn't allowed to read this. It needs the Shop Manager role."
- `wc_too_old`: "WooCommerce {version} is too old. ShelfSync needs 5.8 or newer."
- success: "Connected in {n} ms. WooCommerce {wc}, {count} downloadable products."; warning `no_downloadable_products`: "Connected, but the store has no downloadable products yet."
Error codes (API, shown by the screens):
- `not_found`: "That store no longer exists."
- `store_exists`: "A store with this address is already added."
- `code_taken`: "Another store already uses this two-letter code."
- `keys_missing`: "This store has no keys saved. Enter its consumer key and secret first."
- `keys_required`: "The address now points at a different server. Enter the new keys too, so the old ones aren't sent there."
- `secrets_unavailable`: "Windows Credential Manager couldn't be used, so nothing was changed."
- `busy` (existing): for a test already running: "A test of this store is already running."
- Uninstall (console): "Couldn't read the list of stores, so their Credential Manager entries may be left."
Spacing is stored in milliseconds; the screen shows seconds ("Time between requests").
